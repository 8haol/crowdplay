# ROADMAP.md — 从「一晚的游戏」到「教会活动平台」

2026-09-22 头脑风暴记录。**尚未决策、尚未排期**，只是别让想法丢了。
每一块真要做时，走 `docs/superpowers/specs/` 的 spec → plan → 实现流程，单独上线。

## 起点与判断

- 迎新游戏成功的原因是零门槛：扫码 → 写名字 → 开玩，没人注册登录。平台化的第一个
  流失点就是登录页。
- 一个教会一年的活动量撑不起「刷」的习惯。平台应当是**低频但每次都有理由打开**：
  活动前收到邀请 → 报名 → 现场打卡 → 活动后看相册、领印章。每场活动一个闭环。
- 传福音的价值在活动之后：迎新来了 50 人，下周主日来了几个？谁来过一次再没出现？
  教会端的「跟进」比玩家端的「看活动」更值钱。
- 合规：平台在英国，存的是宗教活动参与记录 + 照片 + 联系方式。宗教信仰属于
  UK GDPR special category data，需要明确同意与隐私政策；照片必须有「我不想出现」的开关。
- **一个还没回答的问题**：平台的第一用户是「来过一次、还没信主的新朋友」（核心是跟进漏斗，
  登录门槛几乎为零），还是「稳定来的会众」（核心是社群信息，可以接受注册）？
  两个答案导向完全不同的第一期。

## 子系统清单（按估计价值排序）

1. **护照跨活动延续** —— 每次活动扫码打卡 = 盖一个章，护照越翻越厚。最强的钩子，
   完全复用现有品牌与盖章视觉。注意：机构之间完全隔离，跨场识别只在同一机构内做。
2. **新朋友跟进流水线（教会端）** —— 来过的人自动进「新朋友」名单；同工标记
   已联系 / 加了微信 / 邀到小组 / 稳定参加；牧者看板：谁三周没出现。
   今天已有的一半：后台完整玩家导出带微信 / WhatsApp。
3. **身份用手机 / 微信，不用密码** —— 一次性验证码或魔法链接；玩家端继续扫码即用，
   账号在背后静默创建，事后补绑。
4. **活动 RSVP + 提醒 + 日历** —— 报名、名额、`.ics`。提醒是难点：微信要公众号模板消息，
   WhatsApp 要 Business API，邮件最简单但留学生不看。
5. **相册** —— 按活动归档、同工上传、成员「找到我的照片」；审核 + 隐私开关；
   Supabase 免费 1GB 存储很快满，要算成本。
6. **同工报名** —— 每场的站点 / 岗位让同工自己认领，直接接现有 staff 机制。
7. **小组 / 团契** —— 加入、点名、小组活动。独立的一整块，放后面。
8. **顺风车** —— 英国教会离校园远，「谁能载我」是真实痛点，也自然建立关系。
9. **多游戏模块化** —— 迎新游戏成为「一场活动可挂载的模块」之一；圣诞版、复活节版。
   主题层（`events.theme`）与主题专属人生事件已经是这个方向的第一步。

## 建议的切分顺序

① 成员身份 + 活动列表 + 打卡盖章 → ② 教会端名单与跟进 → ③ 相册 → ④ 报名 / 提醒 / 同工认领 → ⑤ 小组。
每一块单独出 spec、单独上线；不要一次做成「大平台」。
